# Pulse 2.0 — ветка разработки

База: `8caba19347b7e70b608334fe78f36cf391b1cf8c`. Стабильные APK, исходный ZIP PWA и сценарии публикации не изменены. Эта ветка не публикует сайт и не выпускает APK.

## Реализовано

- Pulse + Aura: графитовая и светлая темы, лайм, фиолетовый акцент и матовые панели. Эмблема «СПК Расписание» в шапке и профиле наследует акцент выбранной темы. Значки установки PWA (192, 512, 180 px) содержат лаймовый вариант эмблемы, поскольку цвет ярлыка на системном экране управляется платформой.
- Первичная настройка студента/преподавателя с поиском по реальным данным СПК и ЦРК. Для преподавателя — вопрос о кураторстве и множественный выбор групп из обоих источников.
- Личный экран, быстрый доступ к курируемым группам, изменение профиля, отмена без потери сохранённого профиля, возврат через «Мой день».
- Каскад карточек, сохранённые горизонтальные свайпы, переходы и смена темы; системное уменьшение движения и настройка отключения анимаций учитываются.
- Отдельное хранение профиля в `pulse.profile.v2`. Ключи прежних настроек, избранного, конструктора, офлайн-данных и Push не меняются.

Существующие поиск, кабинеты, календарь, отправка расписания, 48 палитр, конструктор, восстановление Push и механизм service worker сохранены из сборки стабильной PWA. Настройки конструктора имеют приоритет над оформлением Pulse.

## Сборка и проверка

Нужны Python 3.10+ и Node.js 22+.

```sh
python tools/build_pulse.py
npm install
npx playwright install chromium
npm test
npm run test:browser
python -m unittest discover -s tests -p test_release.py
python -m http.server 4173 --bind 127.0.0.1 --directory _site
```

Открыть `http://127.0.0.1:4173`. Для Windows при использовании системной локали вместо UTF-8 задайте `PYTHONUTF8=1`. Для установленного Microsoft Edge задайте `PULSE_BROWSER_CHANNEL=msedge` перед браузерными тестами. На CI ставятся Chromium и его системные зависимости.

`tools/build_stable_pwa.py` воспроизводит существующие изменения из шага Prepare PWA в `publish-pwa-pages.yml`; при изменении стабильного процесса его нужно синхронизировать. `tools/build_pulse.py` очищает только локальный каталог сборки `_site`, собирает стабильную основу и подключает слой `pulse/`. Исходный ZIP не перезаписывается. Хеш ресурсов входит в имя офлайн-кэша.

Сборка не скачивает Excel и использует встроенные снимки обеих таблиц. Для проверки живого обновления на отдельном тестовом хосте требуется тот же путь `/api/schedule.xlsx` и `/api/rasp_crk.xlsx`, который подготавливает существующий workflow. При отсутствии файлов показывается честное сообщение о сохранённой копии. Не включайте исходные Excel в коммиты.

Workflow `pulse-preview.yml` только проверяет приложение и сохраняет артефакт сборки и скриншоты. В нём нет разрешений на Pages или публикацию Release.

## Проверки и ограничения

Автотесты охватывают студента, преподавателя с кураторством и без него, группы разных источников, поиск в onboarding, отмену, сохранение/перезагрузку профиля, миграцию прежних настроек, избранное, поиск, календарь, отправку, кабинеты, открытие конструктора, обе темы, свайп, уменьшение движения, ширины 320–1440 px и офлайн-перезагрузку. Отдельно проверяются синтаксис всех JS, ресурсы PWA, 48 палитр / 96 вариантов конструктора, обе недели СПК/ЦРК и сохранение восстановления Push.

- Android 1.16.0: актуальных исходников в репозитории нет. В `archives/android` — только историческая версия 1.3.0. Она не используется для пересборки современного приложения. Подписанные APK и Android-публикация не изменены. Для завершения Android нужны актуальный проект и проверка на устройстве; ключ подписи не следует загружать в репозиторий или чат.
- Визуальные изображения из предыдущего чата недоступны через ссылку; оформление реализовано по доступному текстовому описанию Pulse + Aura. Точное совпадение с макетами требует самих изображений.
- Реальная доставка уведомлений на iOS/Android, установка PWA на устройство и обновление APK не проверены. Браузерные тесты не запрашивают разрешение и не отправляют уведомления.
- Локальные браузерные тесты выполнены в Microsoft Edge. Проверка Chromium предусмотрена CI; Safari/iOS требует отдельной проверки перед выпуском.

Перед стабильным выпуском: предоставить актуальный Android-проект и изображения, проверить живое обновление обеих таблиц, доставку Push, установки и обновления на целевых устройствах. Только после этого согласовать перенос в стабильную ветку.
