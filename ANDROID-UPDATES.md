# Публикация APK и обновления приложения

Репозиторий: https://github.com/MarkOfTheDevil/spk-schedule

## Следующая версия

1. Соберите новый APK в исходном Android-проекте, увеличив versionCode и versionName. Подпишите прежним оригинальным ключом. Ключ и исходный проект хранятся отдельно.
2. Запишите описание изменений в текстовый файл (не более 3000 символов).
3. Подготовьте файлы для репозитория:

```bash
python3 tools/prepare_release.py \
  --apk /path/to/SPK-Raspisanie-1.12.0.apk \
  --notes-file /path/to/notes.txt \
  --out release \
  --build-tools /path/to/Android/Sdk/build-tools/35.0.0
```

4. Отправьте каталог release/ в ветку main. Старый APK из этого каталога можно убрать из нового коммита: его копия остаётся в опубликованном Release.
5. Дождитесь успешного задания Publish signed Android releases во вкладке Actions.
6. Проверьте актуальный выпуск и скачивание APK. Последняя метаинформация доступна по адресу https://github.com/MarkOfTheDevil/spk-schedule/releases/latest/download/latest.json.

Для пользователя выпуск новой версии не требует повторной настройки приложения: плашка появляется после очередной успешной проверки. До версии 1.11.0 нужен однократный ручной переход.

## Что проверяет публикация

- Имя пакета ru.spk.schedule и настоящий versionCode/versionName из APK.
- Оригинальный сертификат подписи, Android SDK, размер и SHA-256.
- Нельзя заменить опубликованный APK другим файлом под прежним номером.
- Повторный запуск с теми же файлами сохраняет опубликованный выпуск.
- Незавершённая загрузка остаётся черновиком. APK и latest.json становятся доступны вместе.
- Устаревшее задание не делает старую версию последней.

Приложение дополнительно проверяет скачанный APK и его подпись перед системной установкой.

GitHub Actions использует временный GITHUB_TOKEN с правом contents: write. Приватный ключ подписи GitHub не требуется. Обновления доступны без аккаунта GitHub на телефоне.

## Добавление архивной сборки

Используйте тот же prepare_release.py с --out release-archive/v<версия>. Workflow опубликует оригинальный APK отдельным выпуском, не назначая последней версией. Современный код нельзя пересобирать под старым номером и выдавать за исторический APK.

Автоматические Source code архивы относятся только к этому репозиторию установщиков и сценариев.
